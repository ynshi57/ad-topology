# Stage 1: 目标接入

> 核心思想：YOLO 调优没有天然的"正确答案"，所以入口必须逼用户先把**目标 + 护栏 + 验证信号**说清楚。
> 这 7 个 ★ 字段就是整个闭环的对齐锚——缺了它们，loop 只会朝一个模糊方向刷代理指标。

## Step 1b 三段式 ★ 校验（最先执行的 Gate）

**只看用户在 chat 里的实质描述**；mcap 元数据、sidecar 里已有的数字**都不算**用户描述。
任一 ★ 缺失/占位（"待分析"/"你决定"）→ 暂停，只列缺失字段追问，直到收到实质回答。

| 段 | 字段 | 追问提示 |
|---|---|---|
| §1 | ★ 优化对象 | 哪些相机/场景？（前视 front_* / 鱼眼 / 全部；白天/夜间；近距/远距） |
| | ★ 当前不满意表现 | 具体现象？（远处车漏检 / 红绿灯误报 / 换相机框抖 / 推理太慢…） |
| | ★ 什么算"更好" | 目标指标与方向？（如"远处 car 召回明显↑"、"红绿灯 FP↓"、"延迟↓"） |
| §2 | ★ 护栏指标 | 哪些**不许回退**？给阈值（延迟上限 ms/帧、precision 下限、某类 FP 上限、jitter 上限） |
| | ★ 优化范围 | `infer_cfg`（只调 model/conf/iou/imgsz/device）/ `+preprocess`（含鱼眼校正/分辨率/解码）/ `+finetune`（要训练） |
| §3 | ★ 验证信号 | teacher（大模型伪真值）/ cross_modal（对齐 obj_infer）/ held_out_gt（人工标少量真值）/ llm_judge（VLM 抽样判）；可组合 |
| | ★ 验收方式 | 在哪个 mcap 集、目标指标达到多少、护栏怎么算守住 |

### 询问模板（只列缺失字段）

```
启动 YOLO 调优自闭环前，请补全以下必填信息（不接受"待分析"等占位）:

【§1.什么算更好】<你希望哪个指标往哪个方向变，最好能量化>
【§2.护栏指标】<哪些指标不能因此变差？给个底线，如延迟不超过基线1.5倍、红绿灯误报不增>
【§3.验证信号】<没有真值标注时，用什么当"正确答案"参照？
   teacher=用yolo11x高分辨率当伪真值 / cross_modal=对齐车端obj_infer / held_out_gt=标几十帧真值 / llm_judge=VLM抽样判>
...（每个缺失字段一块）

请回复后我继续。
```

## Step 1c 模式选择

`AskQuestion` 两道单选（exec_mode: strict/flexible；loop_mode: hitl/auto）。已预选则复用；回"默认"= strict+hitl。

## Step 1d 数据准备

- 确认 mcap 是**服务器绝对路径**（`/yolo-detect` 必需，见 references/infra-and-gaps.md）。
- `held_out_gt` 信号 → 确认标注集是否存在；不存在则先规划采样帧与标注方式（Label Tool 目前无 bbox，需扩或外部标注导入）。
- 创建追踪文档（stages/00）。

## 为什么"验证信号"是必填 ★

多数自闭环流程靠一个客观真值/闭环结果来判断"改好没有"。YOLO 检测在 ad-topology 里**没有这种客观真值**
（无 bbox GT、无 mAP），如果不先选定一个验证信号当参照，整个闭环只会朝模糊方向刷代理指标（Goodhart）。
所以这里把"验证信号选择"抬成必填 ★——它是本闭环能否成立的地基。
